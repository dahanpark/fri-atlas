# v2 독립 구조·정합 검토

검토일: 2026-10-22. 원문·spec 및 role-46에 따라 소스·데이터·README·재사용 스킬을 대조했다. 최종 가격 범위 수정과 사진의 동질성 검사 보강까지 확인했다. 제작 소스는 수정하지 않았다. 실제 브라우저·공개 URL·외부 API 실호출은 이 검토 범위 밖이다.

판정: 불합격

결함:

- [내용] (목적·완결성, 구조·형식) **VQ1 / 중요** dist/views.js `exportReport`의 별도 선택 비교와 `items.map` 상세구간 · 별도4곳은 비교표에만 포함되고 조건·출처 상세는 현재 TOP목록 items에만 생성된다. A지역 공식요금 코스를 비교에 담고 B지역을 분석해 저장하면 A코스의 복수가격 범위만 남고 어느 코스·회원조건·시행일·과금단위·출처인지 빠진다. 기존 core.reportHTML에는 선택4곳의 상세조건 보존이 있지만 실제 v2 앱은 views.exportReport를 호출하므로 구버전 테스트 통과가 이를 검증하지 못한다. · 고칠 단계: 디자인·구현 · 지시: 현재목록과 별도선택4곳의 합집합을 ID로 중복제거해 각 코스 조건·출처·시각을 HTML에 한 번씩 포함한다. 리뷰 exportAllowed=false 제외는 합집합에서도 유지한다. A/B지역 교차비교 저장본으로 조건·출처가 남는지 검증한다.
- [내용] (목적·완결성, 구조·형식) **VQ2 / 중요** dist/app.js `analyze`, routing catch 다음 무조건 실행되는 최종 status · 도로 조회 실패/시간초과 시 ‘도로 경로 조회 불가’ 오류를 설정한 직후 성공형 분석완료 메시지가 덮는다. 최종메시지는 사용자가 가격순/거리순을 선택해도 ‘평점→요금확인→일반코스→이름순’이라고 고정된다. 실패와 미조회가 동일한 — 로 남고 사용자에게 필요한 오류 이유도 사라진다. · 고칠 단계: 디자인·구현 · 지시: 분석 목록 생성 성공과 경로 조회 결과를 별도 상태로 보존하고 실패/타임아웃이면 최종 안내에도 경로 실패를 유지한다. 실제 선택 정렬 라벨을 최종 상태에 사용한다. HTTP오류·Abort timeout·정상 응답과 주중/부산 정렬을 각각 확인한다.
- [형식] (언어·톤, 구조·형식) **VQ3 / 보통** dist/index.html `aboutDialog`, dist/views.js `evidence`·exportReport footer, dist/core.js `baseComparison`의 사진행 · 읽기 전 안내에는 ‘사진 사용권과 출처가 확보되지 않아 … 일러스트’와 ‘별점 미연결 코스는 이름순’이라는 v1 설명이 남아 있다. 의령사진1건 확보·추천 fallback이 요금확인/일반코스 우선인 현재 동작과 다르다. 실제사진 코스도 상세 비교에는 ‘사용권 확인 사진 미확보’가 나온다. 복수가격을 범위로 바꾼 뒤에도 근거/저장본 footer는 ‘최저 안내값’으로만 설명한다. · 고칠 단계: 디자인·구현 및 문서 · 지시: 사진은 ‘의령1건 확보, 나머지 미확보’로 현재 범위를 설명하고 코스별 사진 상태를 실제 데이터에 맞춘다. 추천 fallback을 실제 순서와 통일하고, 복수가격은 표시 범위/가격정렬 키 최저값을 구분해 설명한다. 같은 표현이 있는 app·views·core·index·README·구현기록을 전수 대조한다.

전수 확인:

- 지도: app init/merge/renderMap/moveend/debouncer/선택프리뷰, data normalizeNational/within/viewportCourses를 읽었다. 전체 지도마커와 shortList10/20은 다른 경로이며 이동은 로컬 필터링이고 지도 이동 이벤트에 외부 검색 fetch가 없다.
- 요청·경로: analyze의 해외1회조회·bounds·requestId·Abort·캐시·최대20·2초간격과 routing의 m→km/s→분 변환·null·대표점스냅 경고를 대조했다. VQ2는 모든 내부 routing catch와 최종 status에서 확인했다.
- 저장: saved/compared는 코스 snapshot Map으로 보관하며 이전 v1의 ID만 남는 잠김은 현재 코드에 없다. exportReport 현재목록/별도선택/상세근거/리뷰권한제외 네 경로를 전부 확인했다.
- 가격: 18홀·1인 자료만 feeDisplay에 들어가고 복수가격은 범위, 정렬은 최저값이다. 주중/주말·캐디비 단위 미확인·총비용 산출불가·core 조건표시를 확인했다. 현 데이터에 없는 선택일 확정요금이나 추정캐디값을 새로 요구하지 않았다.
- 사진: applyEnrichment의 undefined 동등비교 제거와 photoFor의 stable ID/이름 동질성·URL·권한검사를 확인했다. 실제전국+미매칭공식 코스 전수사진검사에서 의령1곳만 붙는 회귀테스트를 독립 재실행했다. 사진이 다른 골프장에 붙는 이전 결함을 잔존으로 판정하지 않았다.
- 문서: 최신 spec·README·SKILL·제품reference·implementation-v2의 전국표본/네이버 미연결/권리사진1건/외부예약링크 경계를 대조했다. 사용자에게 노출되는 v1 설명의 잔존은 VQ3으로 묶었다.

아슬아슬한 지점:

- 전국수록: 1119 OSM개체와 공식 미매칭1개를 합친1120표본은 영업골프장 총수로 표시하지 않는다. 완전한 전국 운영 명부/좌표대조는 미완이며 문체부PDF 요약539와 추출553 차이는 원천 담당의 해소 대상이다. ‘국내 모든 운영 골프장 확보 완료’라고 보고하면 불합격 사유가 추가되지만 현재 README의 표본 표현은 이 한계를 밝힌다.
- 네이버/전경/예약: 네이버 개별값은 미연결, 실사1곳만 확보, 플랫폼은 일반서비스 이동이며 개별코스 예약 API가 아니다. 최신 spec의 접근불가/부분연결 표시 기준은 넘겼다. 원문 사용자가 요청한 전국 평점·모든 코스 전경·예약 직연동 자체는 아직 부분제공이므로 기능 UI 구현과 자료확보 완료를 분리해 보고해야 한다.
- 가격: 여러조건의 최저값만 대표금액처럼 표시하던 부분은 공통 feeDisplay 범위표시로 고쳐졌다. 선택일·필수비 결측을 0으로 채우지 않는 총비용 차단도 유지했다. 다만 범위 설명의 잔존 문구는 VQ3이다.
- 후기: 제공처 라벨과 네이버 미연결, exportAllowed=false의 HTML 제외를 확인했다. AI요약/표본수/기간/대표성 라벨 누락과 사진 라이선스 직접링크는 사실·근거 검토자의 지적과 함께 보강해야 하며 이 검토가 그 사실검증을 대체하지 않는다.

제안: 없음. 원문 목적의 미확보 자료를 없던 데이터로 채우라는 요구를 추가하지 않았다.
